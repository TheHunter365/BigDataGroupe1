===========================================================================
  PARTIE 2 — CONFIGURATION APPLIQUÉE ET SÉCURITÉS
===========================================================================

---------------------------------------------------------------------------
  2.1 — docker-compose.yml & Mécanismes d'Ordonnancement Strict
---------------------------------------------------------------------------

Le cluster est configuré pour s'exécuter de manière SÉQUENTIELLE et INTELLIGENTE
afin d'éviter tout crash de timing ou de lecture à vide.

ORDRE DE DÉMARRAGE ET ENCHAÎNEMENT DES COMPOSANTS :
  1. La Base Hadoop (SE1) s'allume (namenode + datanodes).
  2. Le service hdfs-init s'exécute pour monter le Data Lake.
     -> Sécurité Doublon : Utilisation de '-test -e'. Si les fichiers de 9 Go
        sont déjà présents sur HDFS, l'upload est sauté instantanément.
     -> Sécurité Volume : Allocation du flag '-D dfs.replication=1' pour fixer
        le coefficient de réplication sur un seul nœud et éviter les alertes.
  3. Barrière de Péage (service_completed_successfully) :
     Tant que hdfs-init n'a pas fini sa tâche et quitté proprement (Exited 0),
     les coeurs de services kafka, spark-submit-job, et flink-jobmanager 
     restent bloqués en statut [Waiting].
  4. Réveil des Pipelines : Dès que le stockage à froid HDFS est prêt, Kafka
     s'allume, ce qui libère automatiquement les producteurs et consommateurs
     applicatifs Python (python-producer et python-flink).

---------------------------------------------------------------------------
  2.2 — hadoop.env (Ajustement HDFS)
---------------------------------------------------------------------------

Modifications et valeurs retenues pour l'environnement Hadoop :
  - fs.defaultFS=hdfs://namenode:9000
  - dfs.replication=1 (Fixé pour optimiser l'espace disque du PC portable local)
  - dfs.permissions.enabled=false (Pour que Spark et Flink écrivent sans barrière)
  - yarn.nodemanager.vmem-check-enabled=false (Obligatoire pour Docker sous Windows)

---------------------------------------------------------------------------
  2.3 — spark-defaults.conf
---------------------------------------------------------------------------

Surcharge de la configuration Spark pour tourner sur YARN :
  - spark.master = yarn (Soumission distribuée gérée par le ResourceManager)
  - spark.eventLog.dir = hdfs://namenode:9000/spark/logs (Historisation HDFS)


===========================================================================
  PARTIE 3 — COUPLAGE ET TOPICS PAR SOUS-SYSTÈME
===========================================================================

---------------------------------------------------------------------------
  SE2 — INGESTION KAFKA — Fichier : ingestion/kafka-producer.py
---------------------------------------------------------------------------

RÔLE : Streamer le dataset local ligne par ligne vers le broker Kafka local.

TOPICS CIBLES : Le script mappe dynamiquement les fichiers vers 5 topics :
  - topic_business, topic_reviews, topic_users, topic_tips, topic_checkins

---------------------------------------------------------------------------
  SE3 — ETL BATCH SPARK — Fichier : etl/scripts/spark_etl.py
---------------------------------------------------------------------------

RÔLE : Lire les fichiers volumineux stockés à l'étape SE1 dans `/data/raw/*`,
       exécuter les gros calculs d'enrichissement et sauvegarder le tout dans
       les répertoires `/data/processed/*` de HDFS.

---------------------------------------------------------------------------
  SE4 — STREAM PROCESSING FLINK — Fichier : streaming/flink.py
---------------------------------------------------------------------------

RÔLE : Consommer le flux en temps réel de Kafka, appliquer des fenêtres de
       temps et renvoyer les alertes.

---------------------------------------------------------------------------
  SE5 — VISUALISATION — Fichiers : dashboard/
---------------------------------------------------------------------------

RÔLE : Stockage analytique final et affichage des Dashboards.

NOTES D'INTÉGRATION :
  - ClickHouse est initialisé via `dashboard/init-db.sql`. Les tables créées
    matchent les structures de données générées par Spark et Flink.
  - Connexion Grafana : Pour lier Grafana à ClickHouse, utiliser l'URL interne
    réseau : http://clickhouse-server:8123 (et non localhost).


===========================================================================
  PARTIE 4 — COMMANDES ET VÉRIFICATIONS POUR LA SOUTENANCE
===========================================================================

LANCEMENT SÉCURISÉ (Prend en compte les modifs de code) :
  docker compose down
  docker compose up -d --build

SUIVRE LE CHECKOUT HDFS AU BOOT :
  docker compose logs -f hdfs-init
  (Doit afficher "skip upload" pour tous les fichiers si déjà présents).

SUIVRE L'INGESTION KAFKA EN DIRECT :
  docker compose logs -f python-producer

SUIVRE LE STREAMING FLINK EN DIRECT :
  docker compose logs -f python-flink
  (Affiche les IDs de parallélisme : "Moyenne (10s):7> (business_id, note)")

ARRÊT TOTAL DU PROJET (SANS PERTE DE DATA) :
  docker compose down
